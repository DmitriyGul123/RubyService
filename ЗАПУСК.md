# Запуск Ruby Service

Инструкции ниже предназначены для Bash. Выполняйте команды из корня проекта.

## Первый запуск

Перед началом убедитесь, что установлены Ruby версии из `.ruby-version`, Bundler и PostgreSQL. Служба PostgreSQL должна быть запущена.

Перейдите в папку проекта. Для Git Bash в Windows:

```bash
cd /c/Users/Dima_PC/Desktop/Ruby/RubyService
```

Для Bash в WSL используйте путь:

```bash
cd /mnt/c/Users/Dima_PC/Desktop/Ruby/RubyService
```

Установите зависимости, подготовьте базу данных и запустите сервер:

```bash
bundle install
./bin/rails db:prepare
./bin/rails server -b 0.0.0.0 -p 3000
```

Откройте приложение на компьютере, где запущен сервер:

```text
http://localhost:3000
```

## Повторные запуски

Когда зависимости уже установлены, а база создана, для обычного запуска достаточно:

```bash
cd /c/Users/Dima_PC/Desktop/Ruby/RubyService
./bin/rails server -b 0.0.0.0 -p 3000
```

Если используете WSL, команда перехода в проект будет такой:

```bash
cd /mnt/c/Users/Dima_PC/Desktop/Ruby/RubyService
```

Сервер остановится после нажатия `Ctrl+C` в окне терминала.

## Доступ с другого компьютера в локальной сети

Сервер запускается с `-b 0.0.0.0`, поэтому он принимает подключения по сетевым интерфейсам компьютера. Узнайте IPv4-адрес компьютера с сервером и откройте с другого устройства `http://АДРЕС:3000`, например `http://192.168.1.25:3000`.

В Windows IPv4-адрес можно посмотреть командой:

```bash
ipconfig
```

Если соединение не устанавливается, проверьте, что устройства находятся в одной сети и входящие подключения к TCP-порту `3000` разрешены брандмауэром Windows.

## Подключение к базе данных

Настройки разработки находятся в `config/database.yml`. Сейчас там указаны PostgreSQL на `localhost`, пользователь `postgres`, пароль `1234` и база `ruby_service_development`. Если ваши локальные настройки PostgreSQL отличаются, обновите их в конфигурации до запуска приложения.

Команду `./bin/rails db:prepare` обычно выполняют при первом запуске, а также после получения новых миграций проекта. Для обычного повторного запуска она не требуется.

## Каталог и тесты

После получения изменений с новыми миграциями подготовьте базу и загрузите демонстрационный каталог:

```bash
./bin/rails db:prepare
./bin/rails db:seed
```

Запустить все модельные и интеграционные тесты:

```bash
./bin/rails test
```

Запустить только модельные тесты:

```bash
./bin/rails test test/models
```

Запустить только интеграционные тесты главного каталога:

```bash
./bin/rails test test/integration/catalog_test.rb
```

Rails автоматически использует отдельную тестовую базу `ruby_service_test`. Перед запуском тестов убедитесь, что PostgreSQL запущен. Тесты используют фикстуры и не требуют предварительного запуска `db:seed`.

## Проверка пути пользователя

Интеграционный тест проверяет весь путь: регистрация нового пользователя, фильтрация каталога, сохранение фильма, просмотр своего списка, выход, повторный вход и удаление сохранённого фильма. Там же проверяются неверный пароль, закрытие списка для гостя и раздельные списки двух аккаунтов.

Запуск только этих сценариев:

```bash
./bin/rails test test/integration/catalog_test.rb
```
